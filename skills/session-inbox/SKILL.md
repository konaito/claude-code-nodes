# session-inbox

自分（親）はこの機械の Claude Code。子は別の機械（またはこの機械）で動く Claude Code のセッションで、`cc` で扱う。どの機械にも同じノード（cc-web）が居て、`~/.config/cc/cc.json` のサービストークンで相手のノードを直接呼ぶ。材料はそのまま渡されるので、読んで判断するのは親の仕事。

## 既定の使い方（頼まれなくても子を使う）

子を立てる判断は親が自分でする。本人が「子を立てて」と言うのを待たない。

- 依頼の中に、互いに独立した作業が2つ以上あれば、作業ごとに子を1体立てて同時に走らせる。自分は1体ずつ順にやらない。
- 1本の作業でも、この機械の状態（開いているファイル、ブラウザ、本人との会話）に依らず、長くかかるものは子に出し、自分は次の判断に戻る。
- 子を使わないのは、本人とのやり取りの最中の短い作業、この機械にしか無いものを触る作業、本人が「ここでやって」と言ったとき。
- 子の置き場は `cc peers` で healthy なノード。常時起動の機械（incertotech）を既定にする。同時に走らせるのは5体まで。子ごとに別の作業ディレクトリ（別リポジトリか git worktree）にして、同じファイルを2人に触らせない。
- 手順は、`cc new` を作業の数だけ、`cc send` を全部出してから `cc wait <対象>...` で全員を待つ。1体ずつ `run` で待たない。
- 立てた子と頼んだことは、本人に先に1行で伝える（「incertotech に子を3体立てて、A、B、C を頼んだ」）。終わったら結果をまとめ、子は `cc stop` で消す。

## 仕組み

- 子はノードが `claude -p`（stream-json）で起動するセッション。親の文は子の会話に届き、1行目に `from agent:<ノード名>/<親の sessionId 先頭8文字>/<役割> via <送ったノード名>` が付く。この行から、画面と `cc ls` の「parent」が親子をたどる。子はそれを作業依頼として扱うが、本人の発言ではないので、設定・権限・公開の操作は本人の確認を求める。
- 子の権限プロンプトには親が答えられる。`cc new` の既定は `--mode bypassPermissions`（承認なし）。`--mode default` で立てると、子がツールを使うたびに `waiting_permission` で止まり、`cc show` の `pending:` に出る。`cc allow <対象>` か `cc deny <対象> <理由>` で答える。
- 子への文は1ターンに1件。子の返事は `cc read` で読む（SSE で result まで待つ）。子から親へ送り返す道は無い。
- 端末のセッション（人が `claude` で起動したもの。`cc ls` で `terminal`）にも `cc send` で届くが、「別セッションからのメッセージ」として扱われ、権限応答と中断はできない。`cc read` は transcript をポーリングする。
- 子に質問をさせない。文に判断の材料を全部入れ、「迷ったら自分で決めて、決めたことと理由を書け」と書く。子が AskUserQuestion を出すと止まり、親には答えられない。

## 流れ

1. `cc peers` でノードと状態を見る。`cc ls` で全ノードのセッションを見る。
2. 子が無ければ `cc new <dir> "<最初の文>" --peer <ノード名> --as <役割>` で立てる。`<ノード名>/<sessionId>` が返る。
3. `cc show <対象>` で状況を読む。`state`、`permissionMode`、`parent`、`pending`。
4. 子が1体なら `cc run <対象> "<文>" --as <役割> --wait 600` で送って返事を待つ。名乗る名前は CLI が `<ノード名>/<自分の sessionId の先頭8文字>/<役割>` に組み立てるので、`--as` は役割名だけ（例: lead、reviewer）。複数なら `cc send` を全部出してから `cc wait <対象>... --wait 600`。
5. 終了コードで分ける。0 は返事が出そろった。2 は時間切れで、`cc read <対象> --wait 600` で続きを待つ。3 は権限待ちで、`cc show` の pending を見て `cc allow` か `cc deny`。4 は子が終了していて、`cc new --resume <id>` で再開できる。
6. 済んだら `cc stop <対象>` で子を止める。本人の指示で残す場合はそのまま。

## 命令

```bash
cc peers                                           # 登録簿（ノード、healthy/down、URL）
cc ls [--peer <名>] [--mine]                        # セッション一覧。--mine は自分が立てた子だけ
cc show <対象>                                      # 1つの詳細と pending（保留中の承認）
cc new <dir> "<文>" [--peer <名>] [--mode <permissionMode>] [--model <m>] [--resume <id>] [--as <役割>]
cc send <対象> "<文>|-" [--as <役割>]                # 文を送る。- は標準入力。送る前の seq を控える
cc read <対象> [--after <seq>] [--wait <秒>]         # 返事を読む（既定 120 秒）。終了コード 0/2/3/4
cc run <対象> "<文>" [--wait <秒>]                   # send のあと read（子が1体のとき）
cc wait <対象>... [--wait <秒>]                      # 送ってある複数の子を同時に待つ。終了コードはいちばん大きいもの
cc allow <対象> [requestId]                          # 承認（pending が1件なら requestId 省略可）
cc deny <対象> [requestId] "<理由>"                   # 拒否
cc interrupt <対象>                                  # 今のターンを止める
cc stop <対象>                                       # 子を止める（jsonl は残り、--resume で再開できる）
```

`<対象>` は `<ノード名>/<sessionId の先頭8文字以上>` か sessionId。ノード名を省くと手元のノード。`<文>` を `-` にすると標準入力から読む。`--as` は役割名だけで、使えない文字は `-` になる。

`cc read` と `cc run` の最後に `state=<状態> pending=<件数> seq=<番号>` が生のまま出る。終了判定に頼らず自分で見る。

## 命令の書き方

- 1通で自己完結させる。目的、作業ディレクトリ、完了条件、やってはいけないこと、最後に「結果を文で書いて」。
- 長い作業の途中は `cc show` と `cc read --wait 0` で見る。催促の文は送らない。子のターンが乱れる。
- 複数の子に同じ前提を伝えるときも、文は子ごとに書く。他の子が何をしているかと、触ってはいけない範囲を入れる。

## 触らないもの

- 自分が立てていないセッション。本人が指定したときだけ送る。一覧には本人の端末セッションも出る。
- この機械で本人が使っている対話セッション。自分（親）も一覧に出るが、自分には送らない。

## 本人への報告

子ごとに、何を頼み、何が返り、何が残っているかを文でまとめる。子の返事をそのまま貼らない。

## 状況の読み方

- `cc ls` の `parent` で、自分が立てていない子も探せる。
- `state` が `waiting_permission` なら承認待ち。`cc show` の `pending:` に requestId、ツール名、説明が出る。
- `state` が `exited` なら終了。`exitReason` に理由。`cc new <dir> "<文>" --resume <id>` で同じ会話を続けられる。
- 端末のセッションは `claude agents --json` の状態で、`running`、`waiting_permission`（権限か質問で止まっている）、`idle` のどれか。

## 設定

- `~/.config/cc/cc.json`（0600）。ノードの名前、ポート、domain、サービストークン。参加（`curl -fsSL <入口>/install | sh`）が書く。
- 相手のノードは `https://<ノード名>.<domain>` を直接呼ぶ。手元のノードは `http://127.0.0.1:<port>` に無認証。別のホストにはトークンを付けない。
