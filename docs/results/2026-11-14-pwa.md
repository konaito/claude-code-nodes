# 画面の PWA 化（PR #50）を本番に配った記録（2026-11-14）

PR #50 をマージした main（e787b2e）を incertotech と vm に配り、Access の Bypass アプリ `ccn-install` に `/pwa` を足した。作業は konaito-pro のノードの PTY の子（ccn-pwa、c2294a04）が行った。依頼は親 meta（4b603e30）から来た。

konaito-pro には配っていない。konaito-pro のノードでは、この子と親を含む PTY のセッションが動いていた。update はノードを再起動し、PTY のセッションを全部止めるので、配るのは親に任せた。

## 結果のまとめ

| 確かめたこと | incertotech（入口） | vm | konaito-pro |
| --- | --- | --- | --- |
| 更新前の中身 | 6e5bfbd（`d71235bb44fc`） | 6e5bfbd（`d71235bb44fc`） | cd2f320（`e0e94b4789bc`） |
| 更新 | 15:31:48〜15:31:49 | 15:32:02 | していない |
| ノードの pid | 68574 から 61805 | MainPID 1075 から 13542 | 変わらない |
| 更新後の中身 | e787b2e（`b568e0fc42fa`） | e787b2e（`b568e0fc42fa`） | cd2f320 のまま |
| 未認証の manifest とアイコン | 200 | 200 | 401（古い版のノードが断る） |

中身の値は、前回までの記録と同じ作りで出した。`src`、`skills`、`bin`、`package.json`、`bun.lock` の各ファイルの sha256 をまとめた値で、`._` で始まるファイルは除く。

incertotech と vm は、teleport（PR #18）が入る前の main だった。今回の配布で teleport も2台に入った。

## 配る前に見たこと

- `ccn ls --peer <台>` で、exited 以外のセッションを見た。incertotech は端末のセッション（x-tl-digest-43、idle）が1件だけだった。端末のセッションはノードの子ではないので、再起動では止まらない。vm は0件だった。
- konaito-pro には、running と idle の PTY が7本あった。

## 配り方

1. e787b2e を `git archive` で `/tmp/ccn-pwa-rollout/a-e787b2e` に取り出し、値が `b568e0fc42fa` であることを確かめた。
2. tar に固め、incertotech には scp、vm には `orb run -m ubuntu` の標準入力で送った。
3. 各台で新しい空のディレクトリに展開し、値が合うことを確かめてから `ccn update --from <dir>` を実行した。値が合わなければ止める作りにした。
4. 2台とも、出力は「更新した: …。node を再起動した。実行物は ccn」で、終了コードは0だった。

## Access の Bypass アプリ

`ccn-install` だけを、e787b2e の `ensureBypassApp` で更新した。hosts は `ccn-*.fybe.jp` と `ccn.fybe.jp` で、今までと同じである。更新の前後に `cf zero-trust access applications list` を控えて比べた。

| アプリ | 変わったこと |
| --- | --- |
| `ccn-install` | `self_hosted_domains` に `ccn-*.fybe.jp/pwa` と `ccn.fybe.jp/pwa` が増えた。id と aud は同じ。方針は `public`（bypass、everyone）のまま |
| `ccn` | 変わらない。id、aud（`58ac2cb3…66e4`）、`oauth_configuration`、方針の `owner` と `nodes` が同じ |
| ほかのアプリ | id と `updated_at` が同じ |

認証なしで読めるようになったのは、`/pwa/manifest.webmanifest` と `/pwa/icon-180.png`、`icon-192.png`、`icon-512.png` だけである。`/pwa/` の下のほかの道はノードが 404 を返す。

## 本番での確認

### 未認証の curl

`ccn.fybe.jp`、`ccn-incertotech.fybe.jp`、`ccn-vm.fybe.jp` の3つで同じ結果だった。

| 道 | 状態 |
| --- | --- |
| `/pwa/manifest.webmanifest` | 200、`application/manifest+json` |
| `/pwa/icon-180.png`、`icon-192.png`、`icon-512.png` | 200、`image/png` |
| `/pwa/nope.png` | 404 |
| `/sw.js`、`/`、`/api/host` | 401 |
| `/skill.md` | 200（前と同じ） |

`ccn-konaito-pro.fybe.jp` は、`/pwa/` の下も 401 だった。Access は通るが、古い版のノードが JWT の無い要求を断るためである。

`https://ccn.fybe.jp/pwa/icon-512.png` の sha256 は、e787b2e の `src/web/pwa/icon-512.png` と一致した。アイコンの `cache-control` は、ノードが返す `max-age=3600` ではなく `max-age=14400` で届き、`cf-cache-status` は HIT だった。アイコンを変えると、入れ替わるまで最大4時間かかる。

### サービストークンを付けた取得

`ccn.fybe.jp` と `ccn-vm.fybe.jp` で、`/` は 200 だった。本文に manifest の link（`crossorigin="use-credentials"`）、`apple-touch-icon`、Service Worker の登録の行があった。`/sw.js` は 200、`text/javascript` だった。manifest の `short_name` は、入口が `ccn`、vm が `ccn-vm` だった。

### Chrome（agent-browser）

agent-browser の Chrome で `https://ccn.fybe.jp/` を開いた。サービストークンは CDP の `Network.setExtraHTTPHeaders` で付け、コマンドの引数には出していない。CDP で読んだ結果は次のとおりである。

- `Page.getAppManifest` の url は `https://ccn.fybe.jp/pwa/manifest.webmanifest`、errors は空だった。
- `Page.getInstallabilityErrors` は空だった。
- Service Worker は scope `https://ccn.fybe.jp/` で active になり、画面を制御していた。
- 画面には3台（incertotech、konaito-pro、vm）が healthy で出た。スクリーンショットを目で見た。

## 手元での確認（マージの前）

- `bun test` は 438 pass、0 fail だった。`bunx tsc --noEmit -p .` も通った。
- 別の設定で 127.0.0.1:4399 にノードを立て、agent-browser の Chrome で開いた。manifest の errors とインストール不可の理由は空で、Service Worker は scope `/` で画面を制御していた。
- Service Worker が動いた状態で、一覧の API は 200 だった。EventSource は、最初の keep-alive が来た15秒後に open した。Service Worker の無い版（konaito-pro の 4323）でも、最初のデータが来るまで open しなかった（9.4秒、動いているセッションのイベントで open）。Service Worker による差は見つからなかった。

## 残っていること

- konaito-pro への配布。PTY のセッションが止まるので、親が時機を決める。
- iPhone と Android の実機でホーム画面に追加できるか。実機では試していない。
- ホーム画面から開いたときに、Safari と cookie や localStorage が分かれるか。分かれる場合は、初回に Access のログインと画面の設定のやり直しが要る。
