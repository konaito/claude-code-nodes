# 子を立てる前に cwd を信頼済みにする（#46、2026-11-13）

ノードが立てた PTY の子が、claude のフォルダ信頼の確認画面（Accessing workspace / Quick safety check）で止まっていた。ノードが claude を起動する前に、claude の設定ファイルに信頼の記録を書くようにした。実測は konaito-pro で、本番とは別の試しのノード（ポート 4391、名前 trustlab）を立てて行った。claude は 2.1.323 である。

## 直す前の実測

素の main（8b3b6a4）の試しのノードで、`~/ccn-trust-lab` の下に PTY の子を立て、8秒後の画面を端末の SSE の replay で読んだ。`~/ccn-trust-lab` とホームは信頼の記録が無い場所である。

| cwd | 確認画面 |
| --- | --- |
| 新しい git リポジトリのルート（`A`） | 出た |
| そのサブディレクトリ（`A/sub`） | 出た |
| git でないディレクトリ（`plain`） | 出た |
| 信頼済みのリポジトリ（claude-code-nodes）の git worktree | 出ない |

確認画面に答えずに止めたとき、上の4つでは claude は `projects` に項目を書かなかった。下の表の `B` では、`hasTrustDialogAccepted: false` の項目を書いた。違いの理由は調べていない。

続けて、`{ "hasTrustDialogAccepted": true }` だけの項目を手で足して試した。

| 足した項目 | 立てた cwd | 確認画面 |
| --- | --- | --- |
| `A`（ルート） | `A/sub` | 出ない |
| `B/sub`（cwd だけ） | `B/sub` | 出ない |
| `B/sub`（cwd だけ） | `B`（ルート） | 出た |

最小の項目で確認画面は出なくなる。ルートに書くとサブディレクトリにも効く。

## claude の書き方

claude が `~/.claude.json` を書く間、ホームを 50ms ごとに見た。`.claude.json.lock` というディレクトリと、`.claude.json.tmp.<pid>.<16進>` という一時ファイルが現れた。claude はロックをディレクトリで取り、一時ファイルから rename で書いている。実ファイルを読んで2文字の字下げで書き戻すと、元の中身と一致した。

## 直したこと

- `src/engine/trust.ts` を足した。`Sessions.create` が、claude を起動する前に呼ぶ。pty、node、受け口、resume の作成は全部ここを通る。
- 書き先は `CLAUDE_CONFIG_DIR` があればその中の `.claude.json`、無ければ `~/.claude.json` である。子に渡すのと同じ環境（ノードの `process.env`）から決める。本番のノードの launchd の環境に `CLAUDE_CONFIG_DIR` は無い。ノードは `Bun.which("claude")` の claude を起動し、cam のコマンドは通らない。
- 書くのは cwd と、cwd が git の中ならルートの2つである。どちらも symlink を解いた実体のパスで書く。
- 既に true なら、ロックを取らずに読むだけで終わる。konaito-pro の 1.2MB のファイルで、1回15〜19msかかった。
- 書くときは、claude と同じロックを取る。3秒待っても空かなければ書かない。30秒より古いロックは、落ちた claude の残りとみなして外す。
- ロックの中で読み直す。読み出しが空のとき、JSON のオブジェクトでないとき、`projects` がオブジェクトでないときは書かずにログを出し、起動を続ける。
- 他のキーはそのままにし、足りない項目の `hasTrustDialogAccepted` だけを true にする。元のモードで一時ファイルを同じディレクトリに書く。rename の直前にファイルの mtime と size を読み直し、変わっていたら捨てて読み直す。読み直しは3回までにした。
- 上書きする前の中身を `.claude.json.ccn-trust.bak`（0600）に1個だけ残す。
- 書いた後に読み直し、項目が残っていなければログに出す。同じノードの中の書き込みは1本ずつにする。
- node の子は、遅延起動で create から起動まで間が空くことがある。起動の直前には書き直していない。`-p` の claude は確認画面を出さないためである。

## 直した後の実測

直したコードで試しのノードを立て直し、新しい git リポジトリ `C` のサブディレクトリ `C/sub` に PTY の子（haiku）を立てた。

- ノードのログに `trust: /Users/konaito/ccn-trust-lab/C/sub, /Users/konaito/ccn-trust-lab/C を信頼済みにした（/Users/konaito/.claude.json）` が出た。
- 8秒後の画面に確認画面は無く、入力欄（`❯ Try "create a util logging.py that..."`）が出ていた。
- `POST /api/sessions/<id>/messages` に「reply with the single word pong」を送ると 200 が返った。messages には user、assistant（`pong`）、result の順に届いた。
- node の子（`-p`）を新しい git リポジトリ `D` に立てると、`D` の項目も書いた。
- 試しの前に控えた `~/.claude.json` と比べると、トップレベルのキーは同じで、消えた項目は無かった。足されたのは試しの項目だけだった。ファイルのモードは 0644 のままだった。

試しのセッションは DELETE（204）で止め、試しのノードも止めた。試しの項目は、同じロックを取る台本で `~/.claude.json` から消した。`~/ccn-trust-lab` と試しの worktree、会話の置き場も消した。

## この修正で変わること

- roots の下のディレクトリは、ノードが子を立てた時点で信頼済みになる。そのリポジトリの `.claude/settings.json` の hooks と許可は、確認なしで効くようになる。
- `hasTrustDialogAccepted` の形は公開の仕様ではない。claude の版を上げて確認画面がまた出たら、まずここを見る。

## 確かめていないこと

- claude の版を上げたときに、項目の名前やロックの取り方が変わらないか。
- claude がロックを取らずに `.claude.json` を書く経路があるか。ある場合、rename の直前の読み直しで多くは避けられるが、その間の短い時間に書かれると片方の書き込みが消える。
